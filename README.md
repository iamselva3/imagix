# Imagix Photography

React + Vite frontend served as Cloudflare Worker static assets. The Worker, KV and R2 API handlers remain unchanged. The existing photo admin page is copied into the Vite build without modification.

## Project tree

```text
imagix/
|-- frontend/
|   |-- index.html
|   |-- vite.config.js
|   `-- src/
|       |-- App.jsx
|       |-- main.jsx
|       `-- styles.css
|-- public/
|   |-- admin/                  # Existing admin page, unchanged
|   `-- assets/                 # Existing admin/logo assets and hero cut-out
|-- src/index.js                # Existing Worker API; unchanged
|-- package.json
|-- wrangler.toml               # Worker static assets now point at dist/
`-- dist/                       # Generated by npm run build
```

## Frontend packages

- `react`, `react-dom` for the site and section components
- `gsap`, `@gsap/react` for component-scoped animation, ScrollTrigger, and Flip transitions
- `lenis` for smooth scrolling
- `vite`, `@vitejs/plugin-react` for local development and production builds
- `wrangler` for local Worker development and Cloudflare deployment

## Development

Use Node.js 20.19 or newer, then install dependencies once with `npm install`.

For the hot-reloading React frontend, start the Worker with built assets in one terminal:

```sh
npm run worker:dev
```

Then start Vite in another:

```sh
npm run dev
```

Open `http://localhost:5173`. Vite proxies `/api/*` and `/media/*` to the Worker on port 8787. The existing `/admin/` page and its existing CSS/JS are served unchanged by the Vite asset bridge.

To preview the built site through Wrangler, run `npm run build` followed by `npx wrangler dev`. Wrangler reads the generated `dist/` directory and keeps `/api/*` and `/media/*` routed through the unchanged Worker.

## Build and deploy

The Wrangler `[assets]` binding in `wrangler.toml` points at `./dist`; the Vite build creates that directory and includes the existing admin page/assets. Deploy the build and Worker together with:

```sh
npm run deploy
```

This runs `vite build` and then `wrangler deploy`. Configure the existing KV namespace ID, R2 bucket, Worker secrets, and allowed origin in the Cloudflare project as before. No Worker API or storage bindings are changed by this frontend rebuild.

## Existing photography

The React app loads Imagix photos from `GET /api/photos` and falls back to sample imagery until the Imagix gallery has photos. The wedding fallback includes one already-public Devi Studio R2 image from its public clients feed; the other fallback images use Unsplash. The main hero cut-out is the single generated visual at `public/assets/hero-couple.png`; replace that path with a studio-approved transparent cut-out when available. The displayed stats and testimonials are examples and should be replaced with verified studio content before launch.

## Existing admin and API

The admin page remains at `/admin/`. It uses the existing signed-token API implementation at `/api/auth/login`, `/api/photos`, and `/media/:id`. The React contact form posts to the existing `/api/contact` endpoint. No API handlers were modified in this frontend update.

Contact requests are retained by the Worker in KV; this configuration does not send email notifications.

## Tuning

- **Light theme accent:** `--accent` in `frontend/src/styles.css`.
- **Portfolio pin length:** `cards.length * window.innerHeight` in the portfolio ScrollTrigger in `frontend/src/App.jsx`.
- **Splash length:** GSAP timeline durations in `Splash` in `frontend/src/App.jsx`; it plays once per session.
- **Hero cut-out:** `/assets/hero-couple.png` in `Hero` in `frontend/src/App.jsx`.
